Who is ready for NU7?

At NU7, every version 4 Zcash transaction becomes invalid and signers need the new consensus branch ID 0x77190AD9. This board tracks wallets, libraries, bridges and swaps from public evidence: GitHub issues, pull requests, releases and source code, re-checked several times a day; the time of the last check is shown.

What the statuses mean

  • FixedA fix is merged, a release is published, the source has the NU7 change, or the issue was closed as done. A release or deploy to users may still be pending; the note says when.
  • In reviewA fix is open and not merged yet.
  • BrokenAn open issue or the current source code shows the problem, and no fix is open.
  • WatchNo machine-checkable evidence either way: a dated report, a conflicting source or a related change.
  • UnknownA lookup failed this hour. A failed lookup never counts as fixed or broken.

What NU7 changes for integrators

  1. Version 4 transactions are rejected from activation, transparent-only ones included (ZIP 2003). Build v5 or v6.
  2. New consensus branch ID 0x77190AD9. v5 and v6 signatures commit to it, so a signer with old constants fails even if it already builds v5.
  3. Blocks every 25 seconds instead of 75 (ZIP 218). The same number of confirmations now takes a third of the time.
  4. Sprout funds become unspendable, because Sprout can only be spent in a v4 transaction.

Source: ZIP 259. Zebra 7.0.0 is the node release that activates NU7; Zebra 6.4.x stops itself around 2 November.
